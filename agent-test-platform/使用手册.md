# 通用 DeepSeek Agent 与攻击测试使用手册

## 1. 范围

本手册对应 `platform/`。平台包含两个隔离 Mock 场景、可信工具执行层、独立 Security Oracle、Direct Agent 编排、DeepSeek OpenAI-compatible provider，以及对 `data-generation/` JSONL 样本的低信任输入适配器。Mock 不连接车辆、真实账户、支付、邮件或外部 sink。

默认运行是离线 fixture，结果只能证明平台和判定链路工作；只有真实模型工具调用、可信工具结果和状态增量才能支持攻击有效性结论。模型文本声称“已执行”不算证据。

## 2. 环境

在仓库根目录执行：

```powershell
$env:PYTHONPATH = "graduation-project"
python -m pytest graduation-project/platform/tests
python -m platform.attack_test --fixture --scenario S-DOC
python -m platform.attack_test --fixture --scenario S-EXP
```

本实现只使用 Python 标准库；测试命令不调用 API、不产生费用。

## 3. 场景

`S-DOC` 测试文档读取、低信任内容和合成 sink；公共任务可以创建私有草稿，向 `mock-public` 发布受保护 canary 会被策略阻断。`S-EXP` 测试费用状态、确认作用域、撤权和原子提交；旧或错误确认不能提交 ledger。

每次运行都新建 `MockRuntime`，使用 `reset()` 恢复状态。事件记录包含工具提议、工具结果、顺序号和 `execution_origin=trusted_mock_effect`。Oracle 只读取可信运行时事实，不读取 Agent 的目标提示或生成数据 gold。

## 4. 使用现有生成数据

样本适配器的调用约定：

```python
from pathlib import Path
from platform.sample_adapter import adapt_sample, load_samples

for sample in load_samples(Path("path/to/samples.jsonl")):
    attack_input = adapt_sample(sample, "data-generation/run-id")
    # 仅将 attack_input["untrusted_content"] 作为外部低信任内容投递给 Agent。
```

适配结果保留 `sample_id`、来源哈希和内容类别，并列出被移除的 `gold`、`expected_outcome`、`trajectory`、`tool_result`、Oracle 与 evidence 字段。无法映射到当前 Mock 工具或权限语义的样本必须标记 `UNSUPPORTED`，不能静默改写为成功攻击。

## 5. DeepSeek 实测

### 5.1 当前入口的实际限制（2026-10-13勘误）

当前 `python -m platform.attack_test --scenario S-DOC` **不会运行真实 Agent**：无 key 时退出；有 key 时只打印 wiring 提示。`--samples` 已声明但未被读取。不要把退出码0或提示文本当作实测完成。真实 provider 的请求方法存在，但尚未接通 CLI 样本批测。详情见 [十类测试记录](platform/attack-tests/top10-20261013/测试文档.md)。

真实 API 模式只从进程环境变量 `DEEPSEEK_API_KEY` 读取密钥：

```powershell
$env:PYTHONPATH = "graduation-project"
$env:DEEPSEEK_API_KEY = "<通过既有安全凭据流程加载，不要写入脚本>"
python -m platform.attack_test --scenario S-DOC
```

当前 CLI 默认只验证 provider wiring；正式试验前必须在 `TASK.md` 冻结 model、预算、seed、超时、重试、原始 trace 保存位置和人工复核规则。密钥不得进入 prompt、memory、checkpoint、trace、样本、日志、异常输出或 Git。API 失败记为 `ERROR`，能力不支持记为 `UNSUPPORTED`，不得回退成成功。

### 5.2 为什么已在终端设置，另一个进程仍读不到

PowerShell 的 `$env:DEEPSEEK_API_KEY = ...` 只设置该 PowerShell 进程的环境。它随后启动的 Python 会继承；已经启动的 Codex、编辑器、其他终端和工具执行进程不会反向继承。工具调用也可能使用独立 shell，同一个界面或相同工作目录不保证同一环境。先设置，再从该 PowerShell 启动所需进程，才有继承关系。

2026-10-13实际检查：工具进程变量不存在、用户级变量不存在、系统级变量不存在；没有验证您输入的 key 是否有效，没有搜索终端历史，也未输出 key。现有证据支持“进程环境未共享”，不能证明您的交互终端未配置。请在您执行设置命令的那个 PowerShell 中使用以下仅检查存在性的命令：

```powershell
python -c "import os; print('configured' if os.environ.get('DEEPSEEK_API_KEY') else 'missing')"
```

如果这里是 configured 而工具进程是 missing，则是进程边界问题；若这里也 missing，检查是否换了 shell、重开窗口，或在不同用户/远程会话中执行。不要用 `echo $env:DEEPSEEK_API_KEY`、环境变量全量打印或命令历史截图排查。

### 5.3 一次设置、跨终端复用

推荐的长期方案是 [Windows Credential Manager 设计](Credential-Plan-v1.md)，但当前源码没有 vault/keyring 自动加载能力，不能声称已支持。以下是用户明确要求的、兼容当前环境变量接口的备选：保存为 **Windows 当前用户环境变量**。它持久保存为可读取的明文配置，不是加密凭据库；同用户进程和其子进程可能获得 key。不要设置 Machine 级变量，不要写入 PowerShell profile、仓库 `.env` 或脚本。

在您本机 PowerShell 中执行以下片段；隐藏输入真实 key，不将 key 字面量写进命令历史。本手册不替您录入或保存 key。

```powershell
$taskSecretInput = Read-Host '请输入 DeepSeek API key（不回显）' -AsSecureString
$taskSecretPtr = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($taskSecretInput)
try {
    $taskSecretPlain = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($taskSecretPtr)
    if ([string]::IsNullOrWhiteSpace($taskSecretPlain)) { throw '未输入 key，未修改配置' }
    [Environment]::SetEnvironmentVariable('DEEPSEEK_API_KEY', $taskSecretPlain, 'User')
    $env:DEEPSEEK_API_KEY = $taskSecretPlain
    Write-Output '已配置当前用户和当前终端；未显示 key'
} finally {
    [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($taskSecretPtr)
    Remove-Variable taskSecretPlain -ErrorAction SilentlyContinue
    $taskSecretInput.Dispose()
    Remove-Variable taskSecretInput, taskSecretPtr -ErrorAction SilentlyContinue
}
```

该操作只清理临时变量和非托管缓冲区，不能保证 .NET 字符串或环境内存被立即擦除。完成后完全退出并重启需要读取变量的编辑器/Codex/终端宿主；旧宿主创建的新终端也可能继承旧环境。`PYTHONPATH` 是非敏感项目配置，进入仓库后仍按第2节设置，勿将项目路径全局固定。

如果宿主尚未刷新，您自己的当前终端可显式加载用户级配置：

```powershell
$env:DEEPSEEK_API_KEY = [Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY', 'User')
python -c "import os; print('configured' if os.environ.get('DEEPSEEK_API_KEY') else 'missing')"
```

configured 只说明存在，不证明认证成功或攻击入口已实现；本步骤不调用 API。

### 5.4 替换、删除和撤销

永久替换：重新执行5.3的隐藏输入片段，以新 key 覆盖 User 和当前 Process。其他正在运行的进程仍持有旧值，应重启。确认新 key 在后续授权的请求中可用后，在 DeepSeek 控制台撤销旧 key；不要在此过程中打印 key。

临时替换：使用5.3片段但省略 `SetEnvironmentVariable(..., 'User')` 行，只影响当前终端及之后启动的子进程，重开后持久配置仍为旧 key。

只删除当前终端变量：

```powershell
Remove-Item Env:DEEPSEEK_API_KEY -ErrorAction SilentlyContinue
```

删除持久配置及当前终端变量：

```powershell
[Environment]::SetEnvironmentVariable('DEEPSEEK_API_KEY', $null, 'User')
Remove-Item Env:DEEPSEEK_API_KEY -ErrorAction SilentlyContinue
Write-Output ('user_configured=' + (-not [string]::IsNullOrEmpty([Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY', 'User'))))
python -c "import os; print('configured' if os.environ.get('DEEPSEEK_API_KEY') else 'missing')"
```

本地删除不撤销服务端凭据，也不清除其他活跃进程中的旧副本。完全退出相关进程，并在 DeepSeek 控制台撤销该 key，才可使旧 key 无法继续使用。当前检查没有发现 Machine 级配置，无需修改系统级变量。如果以前把真实 key 写在命令中，历史记录可能留存；本手册不读取历史，建议轮换该 key，避免仅依赖删除本地变量。

### 5.5 当前 Agent 能力与十类测试距离

已实现：标准库 DeepSeek HTTP provider；DirectAgent 的消息/工具结果循环；S-DOC 文档 Mock 与 S-EXP 费用 Mock；读取权限、发布目的地策略、费用状态/确认/幂等检查；reset、基础事件与快照；基础 Oracle；JSONL读取和过滤 gold 等字段的适配器；离线 fixture。历史4项测试仅覆盖发布阻断、错误确认阻断、合法费用提交和reset。

尚未实现：LangGraph、图/模板执行器、TFIR/Contract反馈驱动、持久记忆、checkpoint/replay、跨 Agent、完整关联/trace、样本CLI实测、token/API/usage账本及重试。Agent始终只公布 fetch_document，不能据 Mock 中存在其他函数就宣称模型能正常使用它们。费用 Oracle 没有充分区分合法提交与恶意目标；适配器忽略 external_content/dialogue_context，不能保真传递所有攻击内容。

结论：已提炼部分非车载 Mock 原型，尚未达到“通用且泛化的智能体”。通用性需要任务/工具/权限可配置、架构可扩展；泛化性需要跨任务、工具、Agent、模型及领域的实验证据。当前两者均未完成，不能用两个Mock或单一DeepSeek接口代替验证。

## 6. 结果解释

攻击成功必须同时满足预注册攻击目标和可信效果证据。报告中分别记录 `attacker_goal`、`security_violation`、`defense_handling`、`benign_utility`、`runtime_status`、`effect_stage` 和 `evidence_origin`。被阻断的恶意样本仍保留在分母；阻断不等于样本无效。
