# OAPT 工作区规范 v4

版本：4.0.0；2026-10-16。本规范服务于 OAPT 三人项目中 A“攻击样本生成”的个人五十日计划。B 负责通用测试平台，C 负责基线复现与已有攻击样本生成工作的复现；A 不实现通用智能体、不复现 C 的已有样本工作。所有计划事实来自四个 OAPT DOCX，进度事实写入 `agent-security/OAPT_研究方案进度管理_三人员分表与总览甘特图.xlsx`。

## 0. 适用范围与公共约束

本文件只约束在 `agent-security/szh/` 工作区内工作的智能体。它不适用于 `agent-security/zzy/`、`agent-security/lhy/` 或 `agent-security/` 根目录的其他工作；这些位置的智能体分别遵守其自身工作区规则和公共规范。整个 `agent-security/` 的公共约束位于 [../AGENTS.md](../AGENTS.md)，本文件必须在其基础上执行，不能削弱公共文件规定的工作区隔离、文件所有权或禁止跨区修改要求。

`szh/` 是 szh 成员的独立工作区。任何在 `szh/` 工作的智能体只能修改本工作区内由用户明确授权的文件，以及公共规范明确授权的共享文件；无权修改 `zzy/` 或 `lhy/` 下的任何代码、数据、文档、配置、生成物、`AGENTS.md`、`TASK.md` 或 README。读取其他成员工作区的公开内容不产生修改权；跨成员协作必须通过用户授权的共享文件、只读报告、版本化接口或会议记录完成。`zzy/`、`lhy/` 中的局部 `AGENTS.md` 和 `TASK.md` 也不能约束或授权 `szh/` 中的智能体。

## 1. 目标、来源与职责

每次工作首先读取 `TASK.md`、本文件、Excel 以及需要核对的四个 DOCX。A 的目标是完成可独立运行的攻击样本生成算法：历史多轮轨迹整理、步骤图抽取、目标能力和安全约束匹配、逐步测试输入生成、证据检查、三值判断、有限反馈、合成场景迁移、对照和交付。A 的个人计划为 D1–D50，起点 2026-10-19，周末不计入工作日。

A 的输入和输出必须能服务当前测试及后续形式化验证。每个步骤使用 `Pre/Goal/Invariant/Observe/Post` Contract，输出 `TestPlan`、证据引用、状态差分和失败关闭条件。不同智能体可有不同工具、能力、身份/权限、资源/车辆状态、信任来源和观察约束，但字段协议必须版本化。

统一方案为十三周整合路线，A/B/C 清单为十周个人路线；冲突须标注“待导师确认”，不得擅自改写。周三/周四（二选一）和周日讨论是用户指定的协作机制，DOCX 未给出固定时刻或议题，实际信息写入 Excel。

## 2. 工作区边界和禁止事项

- 本次 A 任务只允许修改经授权的研究文档、A 算法代码/样例和进度记录；原始 DOCX、references、`data-generation/`、B/C 代码和原始结果只读。
- 禁止连接真实车辆、CAN/ECU、生产服务、真实账号、邮件、支付或外部副作用；只能使用无害文本、合成工具、Mock/数字孪生和本地固定回复替身。
- 不读取、写入或传播 API key、token、个人信息、真实轨迹、商业 Agent 日志、auth store、checkpoint 或模型文件。
- 不把 `local_simulation`、fixture、gold、静态 `expected_outcome`、模型文本或质量代理分数当作真实攻击成功；不删除 blocked、rejected、Unknown、Invalid、重复或失败记录。
- 不等待 B/C 程序或中间数据完成 A 的独立任务。需要外部接口时写成待确认/Unknown，并继续完成可独立验证的部分。

## 3. A 的研究和方法边界

主轨道是授权低信任文本中的多轮间接提示注入测试输入生成。直接用户越狱、持久记忆污染、能力代码安装和身份文件编辑不是 A 主轨道。A 的差异化假设必须可证伪：证据回指、目标能力/信任边界匹配和部分观察三值反馈的组合是否改善可执行性与可审计性；不能把攻击图、多轮、反馈或 LLM 辅助抽取单独包装成创新。GAP、RACE、STAC、AutoDojo 等方法由 C 复现或比较，A 提供同一目标能力、工具、预算、path_id 和结果轴下的 `TestPlan`，不代替 C 做复现。

生成流程固定为：输入来源审计 → 轨迹/图构建 → 工具/权限/状态硬筛选 → 候选生成与标注 → Mock 执行 → 独立观察 → Contract 验证 → 反馈或停止 → 版本归档。`request`、`attempt`、`blocked`、`effect` 和 `violated` 分轴记录；没有 Hard Observable 时只能记 Unknown。

## 4. Excel 强制回填门禁

Excel 是任务完成的必要记录。智能体每完成、开始或阻塞一个 A 日任务，必须自动打开并更新 `A_核心算法` 的对应行：

| 任务 | Excel 行 | 必填更新列 |
| --- | --- | --- |
| Dn | n+4（D1=第5行，D50=第54行） | O 状态、P 完成度、Q 实际开始日期、R 实际结束日期、S 交付/保存位置、T 证据/阻塞、U 备注 |

执行规则：

1. 先读取行内 A:N 的源计划字段，不得用个人解释覆盖原文任务、周目标、任务类型、计划开始/结束日期或来源块。
2. 开始执行时将 O 写为“进行中”，P 写 0–99 的实际完成度，Q 写真实开始日期；未开始的任务保持“未开始”，不预填实际日期。
3. 验收标准、产物和证据全部满足时，O 才能写“已完成”，P 写 100，R 写真实结束日期，S 写产物路径，T 写命令/环境/日志/报告定位，U 写限制、复核情况和接口影响。
4. 只有真实外部条件导致无法继续才写“阻塞”；T 必须包含阻塞原因、发现日期和解除条件，P 保留真实比例。等待 B/C 交付不是 A 任务默认阻塞。
5. 每次修改后保存并重新打开工作簿，核对 `总览甘特图` A 区第 n+5 行仍引用 `A_核心算法` 第 n+4 行的公式。不得把总览公式替换成手工值，不得写入 B/C 的个人任务行。
6. 会议结束后同步更新“讨论交流节点”表：确认日期、时间、参与者、议题、决定、跟进和状态；未确认信息填“文件中未提供/待确认”。

如果 Excel 无法打开、保存或公式校验失败，任务不得标为“已完成”；应在 TASK 和对应 T/U 列记录错误，修复后重新执行回填和重开校验。

## 5. 日任务执行和验收

按 `TASK.md` 的 D1–D50 顺序执行，每天保留输入版本、命令、环境、产物、验收结果和失败日志。D1–D5 冻结边界和最小执行器；D6–D10 冻结轨迹来源和开发/留出集；D11–D20 完成抽取、能力匹配和三值判断；D21–D30 完成逐步生成和四类合成场景；D31–D40 完成对照、故障、去重和留出；D41–D50 完成教程、清洁安装、转换器、回归、报告和交付。

每个候选必须记录 `Source-ID`、来源组、`Graph-Node-ID`、`Test-ID`、约束实例、Schema 版本、观察等级、预算、结果轴和失败原因。训练候选、测试输入、执行轨迹、验证 witness 和文献示例用途分开。形式化验证接口至少核验工具 Schema、权限/状态前置条件、确认顺序、状态差分、证据完整性、预算和失败关闭。

## 6. 证据、合规与协同接口

证据优先级为 Hard Observable（工具、参数、权限、确认、状态差分）高于结构化执行轨迹，高于模型文本和语义推断。`Unknown` 不等于 `Safe`；缺字段、身份/状态冲突、超时、重复、乱序、Guard/Oracle 不可用时失败关闭并保留原始记录。

`data-generation/` 只读。A 可读取其字段和格式以做适配，但不重跑、不改写、不把 B/C 的已有生成或复现成果列为 A 待办。A→B 接口为 `TestPlan + CapabilityConstraint + Contract`；B→A 为 `ExecutionTrace + EvidenceOutcome`；C 提供基线和统计接口。接口不可用时记录待确认并继续 A 的本地 Mock 验证。

## 7. 周会和交接

每周周三/周四二选一讨论进度、问题、证据和后续计划；每周日复盘实际产物、验收差距、风险和下一周五日目标。会后同时更新 Excel 讨论节点和受影响任务行，不能只在聊天中留记录。交接至少包含日期、Dn、来源/Schema、环境、命令、产物、Evidence、Blockers、Handoff 以及对 B/C 的接口影响。

## 8. 完成标准

任务只有在代码/文档产物可定位、Excel 对应行已回填、证据可复核、失败和限制已记录、形式化验证转换字段齐全时才可标为“已完成”。个人阶段不宣称整体平台安全增益、基线优越性或真实车辆安全结论。姓名、会议时刻、正式模型/平台版本、整合排期和最终创新验收口径未在来源中提供时，必须标为待确认。
