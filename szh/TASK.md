# OAPT 工作 A 任务看板 v4

版本：4.0.0；2026-10-16。此看板只管理本人负责的 OAPT-A“攻击样本生成”五十个工作日。B 负责通用测试平台，C 负责基线复现与已有攻击样本生成工作的复现；这些工作已经分别列在 B、C 的甘特图中，A 不重复实现、不重复复现，也不以等待 B/C 的程序或中间数据作为 A 的阻塞条件。四个 OAPT DOCX 是计划事实来源，Excel 是唯一进度记录入口。

## 完成、状态与授权规则

- 任务状态只使用：`未开始`、`进行中`、`已完成`、`阻塞`。完成度只填写 0–100% 的数值；没有可复核证据时不得填写“已完成”或 100%。
- A 的日任务以 Excel `A_核心算法` 表为准。第 n 个工作日对应第 n+4 行，亦即 D1 对应第 5 行、D50 对应第 54 行；总览中 A 的对应行是第 n+5 行。计划字段来自 DOCX，不能用实际日期覆盖。
- 个人五十日按每周五个工作日计算，起点为 2026-10-19（周一），D50 为 2026-12-25；周末不占用 D1–D50。该起点是本次进度表采用的排期，若导师修改，必须在 Excel 和本文件同时记录。
- 每周安排一次周三/周四（二选一）讨论和一次周日复盘。DOCX 未提供固定时间和议题，会议日期、确认时间、实际议题和决定写入 Excel“讨论交流节点”表。
- A 可独立完成轨迹整理、步骤图、能力/约束匹配、逐步生成、三值判断、有限反馈、合成场景、对照、故障、留出、教程和交付。A 不负责通用智能体、LangGraph/模型平台、B 的执行观察器、C 的基线复现或已有攻击样本生成工作的再现。
- 任何真实车辆、车辆控制器、生产服务、真实账号、凭据和外部副作用均不在 A 的个人阶段内。所有执行样例使用无害文本、合成工具和本地 Mock/数字孪生；没有 Hard Observable 时保留“未知”。

## 分类与分级子任务

### A0：研究边界、方法差异和接口

- 主轨道是授权低信任文本（例如模拟邮件、文件、日历或工具响应）中的多轮间接提示注入测试输入生成；直接用户越狱、持久记忆污染、能力代码安装和身份文件修改不属于 A 主轨道。
- 每个候选必须绑定历史来源、目标能力、工具/参数、身份/权限、资源或车辆状态、信任来源、观察接口和预算。不同智能体可以使用不同约束实例，但字段协议和证据等级必须版本化。
- A 的可检验差异是：历史轨迹的证据回指、按目标能力/信任边界的迁移约束、以及部分观察下的三值推进共同决定候选；攻击图、多轮、反馈或语言模型辅助抽取单独使用均不宣称为创新。GAP、RACE、STAC、AutoDojo 等由 C 负责复现或比较，A 只提供可配对的 TestPlan 和接口说明。
- A 输出 `HistoricalTrace → AttackGraph → TestPlan`。每步写为 `τ=(Pre, Goal, Invariant, Observe, Post)`，并携带 Schema 版本、证据引用、约束实例和 `Test-ID`。B 的执行结果只能作为反馈输入；A 不充当可信 Oracle。
- 生成数据同时服务当前测试和后续形式化验证：验证器检查工具 Schema、权限和状态前置条件、确认顺序、状态差分、证据完整性、预算和失败关闭条件。`request` 不等于 `effect`，`expected_outcome` 不等于实际结果，`Unknown` 不等于 `Safe`。

### A1：D1–D5 问题、范围、环境和最小执行器

完成 D1–D5 时，必须冻结研究问题、允许/禁止输入、数据字段、无害本地工具、固定回复模型替身、重置方式和最小运行命令；这只是 A 的隔离算法执行器，不是通用智能体实现。

### A2：D6–D10 轨迹与标注

只整理有来源的历史多轮轨迹，建立人工示范步骤图、来源组、排除原因、开发集和留出集。不得把 C 已完成或计划复现的已有攻击样本当作 A 的复现任务；A 只定义自己需要的输入格式和映射接口。

### A3：D11–D20 图抽取、能力匹配和状态判断

先规则后模型辅助，保留原文证据编号和错误结果；先做工具/权限/状态硬筛选，再排序。三种判断为已完成、明确未完成、暂不能确定；证据冲突、缺失或超时不得自动升级。

### A4：D21–D30 生成循环和跨智能体约束

每次只生成当前步骤，执行一次，观察一次，再决定前进、换候选或停止；有限重试、轮数和费用预算必须显式记录。Email、File、Calendar、Vehicle 只使用合成场景，保留四类约束实例及合法、阻断、证据不足样例。

### A5：D31–D40 对照、故障和留出

每项对照只移除一个机制：可见信息、反馈、图、匹配、Contract 或三值状态。超时、重复、乱序、格式错误、状态冲突和 Unknown 全部保留；留出数据按来源组/任务/工具/路径隔离，不能用于调参。

### A6：D41–D50 复核、交付和形式化验证转换

教程、数据说明、版本哈希、来源/许可审计、转换器、回归、外部事件 fixture、manifest 和个人报告必须能在干净目录中复核。转换器把每步 Contract、证据引用、状态差分和失败关闭条件导出为后续验证输入；不把本地模拟或静态预期写成真实攻击成功。

## 研究证据、数据边界和接口

- 证据等级从强到弱为：工具/参数/权限/确认/状态差分等 Hard Observable；结构化执行轨迹；模型文本和语义推断。低等级证据只能形成候选或 Unknown。
- 每条样本至少记录 `Source-ID`、来源组、`Graph-Node-ID`、`Test-ID`、`Agent-Config-ID`、约束实例、Schema 版本、观察等级、seed/预算、结果轴和失败原因。生成、执行、验证 witness、训练候选和文献示例分开存储。
- `data-generation/` 和 references 只读。A 可以复用已存在的字段和格式作为输入适配，但不复现 B/C 已完成或计划中的攻击样本生成工作，不篡改原始样本、gold、静态 expected outcome 或日志。
- A→B 交付 `TestPlan + CapabilityConstraint + Contract`；B→A 返回 `ExecutionTrace + EvidenceOutcome`；C 返回基线和统计接口。接口缺失时 A 记录 Unknown/待确认并继续可独立部分。

## 会话交接与本次记录

每次周三/周四会议和周日复盘均记录本周已完成 Dn、证据位置、阻塞、决定和下周目标，并同步到 Excel“讨论交流节点”及受影响的 A 任务行。交接记录至少包含：日期、Dn、来源/Schema、命令与环境、产物、验收结果、Evidence、Blockers、Handoff 和是否影响 B/C。

当前未确认项：A/B/C 个人姓名、会议具体时间、统一方案十三周与个人十周的最终合并排期、正式模型/平台版本、真实平台联调预算和导师对最终方法差异的验收口径。未确认项不得在 Excel 中填写为事实。
