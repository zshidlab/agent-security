# 轨迹字段解释（trace-1.0）

版本：1.0.0（D03，2026-10-17）。输入示例为合成维修对话，来源 `source-synthetic-maintenance-001`，用途是本地 Schema 和编号校验。

## 顶层与轮次

`schema_version` 固定为 `trace-1.0`；`source.source_id`、`source_group` 回指来源；`synthetic=true` 防止把 fixture 当成真实轨迹；`task_id` 绑定一次任务。每个 `turn` 有独立 `turn_id`，消息和事件只能属于该轮。

## 消息与事件

消息保存 `message_id`、说话人、原文、信任级别和 `missing_reason`。外部文本是 `low_trust_external`，不能转化为 `user_authorized`。事件区分 `tool_request`、`tool_result`、`state_diff`，并保存 `event_id`、`tool_call_id` 和请求。工具请求与真正执行分开记录；没有工具事件时不得从“已修改”文本生成效果事件。

`request`、`attempt`、`blocked`、`effect`、`violated` 是独立结果轴。`effect` 只有出现 Hard Observable 状态差分才可为 `observed`；否则写 `Unknown`，并在 `missing_reason` 说明。缺字段由 Schema 给出 JSON 路径，编号重复由语义校验给出事件或消息编号。

## 语义校验规则

1. 全部 `task_id`、`turn_id`、`message_id`、`event_id`、`tool_call_id` 在各自命名空间唯一；重复编号拒收。
2. `tool_result`/`state_diff` 必须关联已有 `tool_request` 的 `tool_call_id`；模型文本本身不构成事件。
3. `synthetic` 必须为 `true`，缺失原因必须保留在原记录，不用默认值掩盖。
