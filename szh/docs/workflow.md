# 日任务执行流程

版本：1.0.0；2026-10-17。适用于 OAPT_A D01–D50。本文是公共执行步骤；每日日文档补充本日具体行为和交付要求。

## 1. 选日与读取

1. 读取路径相关的 AGENTS、[TASK](../TASK.md)、本流程、四个原始 DOCX 中需核对的部分和共享 Excel。用户指定日则按指定范围工作；用户授权继续计划时，从 Excel 找最早未验收完成的一日。仅要求调整文档时不启动任何日任务。
2. 打开 `docs/tasks/DNN.md`，核对 Excel `A_核心算法` 源行 A:N 和 DOCX 对应非空正文块。日文档是实施方案；源计划变更或快照冲突先记录待确认，不静默修改原文。
3. 读取依赖日的实际交付和最近一次 handoff，不只看计划路径。确认目标属于 szh，检查目标目录有无更具体约束。后续只按需读取本日输入，避免每次加载全部五十份方案。
4. 缺输入时分清程序缺陷、研究负结果和真正外部阻塞。可以独立实现与 Mock 验证的部分继续；不等待 B/C，也不以虚构数据补成真实来源或真实结果。

## 2. 开始与运行记录

1. 实际执行获授权后，读取对应行，将 O 写“进行中”、P 写真实 0–99、Q 写真实开始日期；未开始的日不预填日期。用户仅授权本地修改而未授权共享回填时先记录需要的授权范围，不能把本地说明当作共享写权限。
2. 创建 `records/DNN/<run-id>/`，从 [模板](templates/daily-record.md) 建立 `daily-record.md` 及必要伴随文件。填实际环境、输入来源/哈希和待验证目标，结果先留“未执行”，运行后再填事实。
3. 按当天步骤实现 `algorithm/` 中对应模块和正式文档；输入输出采用版本化 Schema。阶段结果保留 request、attempt、blocked、effect、violated 各轴，未知值不能当作否或安全。
4. 记录每条真实命令、工作目录、退出码和输出位置。错误、拒绝、Unknown、Invalid、重复和超时同样留证；修复重跑新建记录并关联前次。

## 3. 验证与特殊门槛

1. 先按源计划的验收标准和失败处理检查，再运行当天列出的正负行为用例及受变更影响的必要回归。测试应检查实际行为和证据，不能只对照静态预期或检查文件存在。
2. 从 `szh/` 执行 `python -B scripts/check_workspace.py --day DNN` 验证文档结构；产物完成后加 `--deliverables` 检查交付路径存在且非空。此检查不运行算法、不证明测试通过、不写 Excel。
3. 含代码的日文档约定 `algorithm/tests/test_dNN_*.py`。D02 配置依赖及导入路径后，用文档中的 `python -B -m pytest -p no:cacheprovider ... -q` 运行；尚未实现的测试路径只是计划。纯文档日记录逐条复核依据，避免添加只检查标题存在的无效测试。
4. D09 必须实际隔日至少一天重标，保留两次日期与分歧。D13 固定回复只能验证模型接口；真实模型抽取部分未验证时不得宣称模型质量或完整执行。D44 明确还需小规模真实模型调用；离线部分可独立完成，真实调用在当前凭据限制下待明确授权兼容方式，不因离线通过就写 100%。
5. 公开候选数量、开发样本量、十条参考图、五例报告、十对去重及演示计时等源门槛都用实际数量验收，不能降低为“已准备模板”。没有 Hard Observable 的结论保留 Unknown。本地 Mock 不支撑真实攻击成功或整体车辆安全结论。

## 4. Excel 回填与重新打开

Dn 对应 `A_核心算法` 第 n+4 行、`总览甘特图` 第 n+5 行。只在授权范围内写 A 行 O:U：

| 列 | 内容 |
| --- | --- |
| O | 未开始 / 进行中 / 已完成 / 阻塞 |
| P | 真实完成度 0–100 数值；只有满足全部验收才为 100 |
| Q / R | 真实开始 / 真实结束日期；未结束不提前填 R |
| S | 本日正式交付的可定位路径 |
| T | 命令、环境、运行记录、证据或阻塞原因、发现日期和解除条件 |
| U | 限制、复核结果、接口影响和待确认事项 |

写入前重新读取当前工作簿，避免使用早先副本覆盖他人更新；保留样式、公式、其他工作表和 B/C 数据。工具不可用或工作簿被占用时，在日记录与 TASK 临时异常区保存待写字段，不绕过锁或覆盖别人的版本。阻塞只用于真实外部条件，不能把普通待做代码写成外部阻塞。

保存关闭后重新打开同一文件，核对 O:U 的实际保存值。总览是精选字段汇总，按实际列映射检查，不能假定整行连续复制：

| 总览列 | A_核心算法源列 |
| --- | --- |
| B:I | A:H，依次对应编号、计划日期、来源、标题、操作、周目标和类型 |
| J / K | O / P：状态 / 完成度 |
| L / M / N | S / T / U：交付位置 / 证据阻塞 / 备注 |
| O:BL | 按总览本行 C/D 计划起止日期生成甘特显示的公式 |

以 D01 为例，总览 `B6` 引用 `A_核心算法!A5`，`J6` 引用 `A_核心算法!O5`，`N6` 引用 `A_核心算法!U5`。保持引用和甘特公式，不改成手写值。Q/R 实际日期在 A 表核对，总览没有直接引用这两列。图表显示需要表格软件重算时另行核对，不凭缓存显示判断保存成功。

```powershell
python -B scripts/check_workspace.py --sources
```

此命令只读比较 A:N 与基线、四个 DOCX 哈希和全部 A 区引用公式；不会保存工作簿，不代替核对实际回填 O:U、重开后的显示及其他成员数据。工作簿哈希会随合法进度写入改变，因此 manifest 的 `initial_sha256` 仅作搭建时基线，不要求后续整本哈希永远不变。

如果无法保存或重开校验失败，本日不得标完成。若工作簿不可写，也不可能当时写入 T/U：先在本地留证，恢复后补回填并重新校验。会议结束按实际已确认内容更新讨论交流节点和受影响 A 行；未确认写“文件中未提供/待确认”。

## 5. 收尾与交接

1. 源验收、正式产物、行为测试、证据与 Excel 回填/重开都满足后才记完成。部分完成保留真实比例、剩余动作和最小失败输入。
2. `handoff.md` 写日期、Dn、来源/Schema、环境、命令、产物、Evidence、Blockers、下一步和 B/C 接口影响；不给其他工作区派写入任务，不宣告共享接口已被双方接受。
3. 运行 `git diff --check`、`git status --short --ignored -- .`，核对正式文件是否意外被忽略、生成物是否都经过分类。本地缓存与临时环境放系统临时目录，不新增 `szh/.gitignore`，不擅改父级忽略规则。
4. 对用户报告实际完成和未完成、关键验证及限制。目录搭建、结构检查通过和计划文档齐备都不等于完成当天研究任务。
